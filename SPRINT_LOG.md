# Журнал спринтов

## Спринт 1 «Заказчик пришёл с проблемой»
**План:** определить требования, подготовить репозиторий и каркас приложения.
**Роли:** Алина: PO и настройка Git; Егор: LD и проверка запуска на другом компьютере.
**Результат:** составлены 7 User Stories с критериями приёмки, README, структура проекта, меню и пункт «Показать оборудование» на 6 демонстрационных записях, первые 3 тест-кейса; у каждого участника есть собственные коммиты.
**Ошибки:** Егор сначала по ошибке создал отдельный локальный репозиторий вместо клонирования, повторил работу через клонирование; активация окружения на Windows потребовала разрешить выполнение скриптов PowerShell.
**Передача ролей:** Алина становится LD, Егор QA/DevOps. Задачи на Спринт 2: добавление с проверкой данных, тесты, уточнение User Stories.

## Спринт 2 «Оборудование под контролем»
**План:** добавление и просмотр оборудования с проверкой данных.
**Роли:** Алина: LD и функции PO; Егор: QA/DevOps.
**Результат:** команды «Добавить» и «Просмотреть» работают, добавлена проверка (пустые поля, тип и состояние из списков, уникальный номер), логика вынесена в функции, 7 автотестов, обновлены User Stories (поля, примеры корректных и ошибочных записей); работа выполнена в отдельных ветках и слита в main после просмотра.
**Ошибки:** файл с тестами был создан с неверным именем и перенесён в папку tests.
**Передача ролей:** Алина становится QA/DevOps, Егор PO. Задачи на Спринт 3: поиск, изменение, удаление.

## Спринт 3 «Инвентаризация без хаоса»
**План:** поиск, изменение и удаление записей.
**Роли:** Алина: QA/DevOps; Егор: PO и функции LD.
**Результат:** поиск по номеру и кабинету, изменение состояния и кабинета, удаление с подтверждением, сообщение «Не найдено.», приёмочный чек-лист, 20 автотестов, журнал ошибок.
**Ошибки:** D-1, функция get_items() отдавала общие записи, из-за чего один тест влиял на другой (1 failed, 19 passed); исправлено, после исправления проходят все 20 тестов.
**Передача ролей:** Алина становится PO, Егор LD. Задачи на Спринт 4: сохранение и загрузка JSON, обработка ошибок файла.

## Спринт 4 «Данные не должны пропадать»
**План:** постоянное хранение и восстановление данных.
**Роли:** Алина: PO и функции QA; Егор: LD.
**Результат:** модуль storage.py (загрузка при старте, сохранение после изменений), обработка отсутствующего, пустого и повреждённого файла (повреждённый файл сохраняется как .broken), файл data/inventory.json с 10 записями, тесты файлового хранения, дополненный README, черновик Dockerfile.
**Ошибки:** новых дефектов не найдено.
**Передача ролей:** Алина становится LD, Егор QA/DevOps и функции PO. Задачи на Спринт 5: фильтрация, удаление дублирования, расширение тестов, инструкция пользователя.

## Спринт 5 «Проверка на прочность»
**План:** улучшить надёжность и подготовить продукт к передаче.
**Роли:** Алина: LD; Егор: QA/DevOps и функции PO.
**Результат:** фильтрация по состоянию, убрано дублирование кода в inventory.py, набор тестов расширен до 43, регрессионная проверка и отчёт о тестировании, инструкция пользователя, список ограничений, отметки выполнения User Stories и чек-листа.
**Ошибки:** новых критических дефектов не найдено.
**Передача ролей:** Алина становится QA/DevOps и функции LD, Егор PO. Задачи на Спринт 6: финальная проверка, документация, демонстрация.

## Спринт 6 «Сдача системы заказчику»
**План:** завершить документацию, провести демонстрацию, защитить проект.
**Роли:** Алина: QA/DevOps и функции LD; Егор: PO.
**Результат:** финальный прогон тестов и проверка установки с нуля, описание архитектуры, финальная сводка требований и функций, комплект документации, демонстрация полного сценария: добавить, найти, изменить, сохранить, перезапустить, удалить.
**Ошибки:** новых дефектов не найдено.
**Передача ролей:** проект сдан.

Спринты 1-6 завершены, проект готов к защите.
