# User Stories

## Ситуация
В колледже теряется информация о компьютерном оборудовании: данные ведутся
на бумаге и в разрозненных файлах, непонятно, что и в каком кабинете стоит,
в каком оно состоянии и что списано. Нужна простая программа учёта инвентаря.

## Истории

**US-1. Просмотр списка**
Как лаборант, я хочу просматривать список всего оборудования, чтобы видеть, что есть в колледже.
Критерии приёмки:
- [ ] выводятся номер, тип, наименование, кабинет и состояние каждой записи;
- [ ] если записей нет, выводится сообщение «Список пуст».

**US-2. Добавление оборудования**
Как лаборант, я хочу добавлять новое оборудование, чтобы список всегда был актуальным.
Критерии приёмки:
- [ ] запись создаётся при заполнении всех обязательных полей;
- [ ] пустые поля не принимаются;
- [ ] запись с уже существующим инвентарным номером не создаётся, выводится понятная ошибка.

**US-3. Поиск по инвентарному номеру**
Как лаборант, я хочу находить компьютер по инвентарному номеру, чтобы быстро узнать, в каком кабинете он находится.
Критерии приёмки:
- [ ] по существующему номеру показывается карточка;
- [ ] по неизвестному номеру выводится «Не найдено»;
- [ ] пустой ввод не приводит к аварии.

**US-4. Поиск по кабинету**
Как заведующий кабинетом, я хочу видеть всё оборудование своего кабинета, чтобы проводить инвентаризацию.
Критерии приёмки:
- [ ] по номеру кабинета выводятся все записи этого кабинета;
- [ ] если в кабинете ничего нет, выводится сообщение об этом.

**US-5. Изменение записи**
Как лаборант, я хочу менять состояние и кабинет оборудования, чтобы отражать ремонт и перемещения.
Критерии приёмки:
- [ ] состояние выбирается из: исправно / требует ремонта / списано;
- [ ] изменения видны при повторном просмотре;
- [ ] для несуществующего номера выводится «Не найдено».

**US-6. Удаление записи**
Как лаборант, я хочу удалять ошибочные записи, чтобы список не засорялся.
Критерии приёмки:
- [ ] перед удалением запрашивается подтверждение;
- [ ] при отказе запись остаётся;
- [ ] для несуществующего номера выводится «Не найдено».

**US-7. Сохранение данных**
Как заведующий, я хочу, чтобы данные сохранялись между запусками, чтобы не вводить их заново.
Критерии приёмки:
- [ ] после перезапуска записи на месте;
- [ ] отсутствие файла данных не вызывает сбой.

## Уточнение к US-2 (Спринт 2): поля карточки и примеры записей

| Поле | Правило |
|---|---|
| Инвентарный номер | обязательное, уникальное (например INV-007) |
| Тип | обязательное, одно из: ПК, монитор, принтер, проектор, другое |
| Наименование | обязательное |
| Кабинет | обязательное |
| Состояние | обязательное, одно из: исправно, требует ремонта, списано |

Примеры записей:

| Запись | Корректна? | Результат |
|---|---|---|
| INV-100, ПК, HP ProDesk, 110, исправно | да | запись добавлена |
| INV-101, монитор, Dell P2419, 205, требует ремонта | да | запись добавлена |
| INV-001, ПК, Другой ПК, 110, исправно | нет (номер занят) | ошибка «Запись с номером INV-001 уже существует.» |
| (пусто), ПК, HP ProDesk, 110, исправно | нет (пустой номер) | ошибка «Поле «Инвентарный номер» не может быть пустым.» |
| INV-102, frf, HP ProDesk, 110, исправно | нет (неверный тип) | ошибка «Тип должен быть одним из: ...» |
| INV-103, ПК, HP ProDesk, 110, df | нет (неверное состояние) | ошибка «Состояние должно быть одним из: ...» |
