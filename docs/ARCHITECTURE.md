# Архитектура

## Модули
| Модуль | Назначение |
|---|---|
| `main.py` | Консольное меню и диалоги ввода-вывода. Логики проверки данных в нём нет: он вызывает функции других модулей и печатает результат |
| `inventory.py` | Операции с записями без ввода-вывода: проверка, добавление, поиск, фильтрация, изменение, удаление |
| `storage.py` | Чтение и запись файла `data/inventory.json`, обработка отсутствующего и повреждённого файла |
| `tests/` | Автотесты: `test_inventory.py` (операции с записями), `test_storage.py` (файловое хранение) |

## Поток данных
1. При запуске `main.py` вызывает `load_items()` из `storage.py` и получает список записей и, если нужно, предупреждение.
2. Пользователь выбирает пункт меню, соответствующий диалог запрашивает данные.
3. Диалог вызывает функцию из `inventory.py`. При ошибке данных функция вызывает `ValueError`, диалог перехватывает его и печатает сообщение, список не меняется.
4. После успешного добавления, изменения или удаления `main.py` вызывает `save_items()`.

## Ключевые функции `inventory.py`
| Функция | Что делает |
|---|---|
| `validate_item` | Проверяет, что поля не пустые, тип и состояние допустимы, номер уникален |
| `add_item` | Проверяет данные, очищает пробелы и добавляет запись |
| `find_by_number` | Ищет запись по номеру без учёта регистра и пробелов, возвращает запись или `None` |
| `find_by_room`, `filter_items` | Отбирают записи по кабинету и/или состоянию |
| `update_item` | Меняет кабинет и/или состояние с проверкой |
| `delete_item` | Удаляет запись только при подтверждении, иначе оставляет |
| `get_items` | Возвращает независимые копии демонстрационных записей (исправление ошибки D-1) |

## Решения
- Логика отделена от ввода-вывода, поэтому её можно проверять тестами без клавиатуры.
- Ошибки данных сообщаются исключением `ValueError`, а не аварией программы.
- Повреждённый файл не удаляется, а переименовывается в `.broken`, чтобы данные не пропали незаметно.
- Файл записывается через временный файл и замену, чтобы при сбое не остаться с недописанным файлом.
