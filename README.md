# Система учёта инвентаря компьютерных классов

Консольное приложение на Python для учёта компьютерного оборудования колледжа: просмотр, добавление, изменение, удаление и поиск инвентарных записей. Данные сохраняются в JSON-файле.

Запись об оборудовании: инвентарный номер (уникальный), тип, наименование, кабинет, состояние.

## Требования
- Python 3.11 или новее
- pytest (для тестов)

## Установка и запуск

macOS / Linux:
```
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
python3 main.py
```

Windows (PowerShell):
```
python -m venv .venv
.venv\Scripts\Activate.ps1
pip install -r requirements.txt
python main.py
```
Если PowerShell запрещает запуск скриптов, один раз выполните `Set-ExecutionPolicy -Scope CurrentUser RemoteSigned`.

## Меню
1. Показать оборудование
2. Добавить оборудование
3. Найти оборудование
4. Изменить запись
5. Удалить запись
0. Выход

## Хранение данных
Записи хранятся в файле `data/inventory.json` (JSON, кодировка UTF-8). Программа загружает файл при запуске и сохраняет его после каждого добавления, изменения и удаления. В репозитории лежит файл с 10 примерами записей.

Поведение при проблемах с файлом:
- файла нет или он пустой: программа запускается с пустым списком, файл создаётся при первом сохранении;
- файл повреждён (неверный JSON или неверная структура): он переименовывается в `data/inventory.json.broken`, программа выводит предупреждение и начинает с пустого списка, исходные данные остаются в копии.

## Пользовательские сценарии
1. Лаборант добавляет новый компьютер (пункт 2), затем находит его по номеру (пункт 3, режим 1).
2. Заведующий кабинетом смотрит всё оборудование кабинета (пункт 3, режим 2).
3. Лаборант меняет состояние оборудования после ремонта или списания (пункт 4).
4. Лаборант удаляет ошибочную запись (пункт 5) и подтверждает удаление.
5. После перезапуска программы все изменения на месте.

Поиск по состоянию доступен в пункте 3, режим 3.

## Тесты
```

```
Тесты лежат в папке `tests/`.

## Docker (необязательно)
Если Docker установлен:
```
docker build -t inventory .
docker run -it --rm -v "$(pwd)/data:/app/data" inventory
```
Запуск в обычном Python обязателен, Dockerfile рассматривается как дополнительный результат.

## Структура проекта

## Известные ограничения
- Интерфейс только консольный, графического интерфейса нет.
- Изменять можно только состояние и кабинет, остальные поля после создания не меняются.
- Нет разграничения доступа и истории изменений.
- Файл данных рассчитан на одного пользователя: одновременная работа нескольких людей с одним файлом не поддерживается.
- Dockerfile не обязателен, запуск проверяется в обычном Python.
